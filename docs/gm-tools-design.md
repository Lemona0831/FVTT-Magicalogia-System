# 플롯 토큰 · GM 도구 설계

- 상태: 설계 초안 (코드 없음). 사용자 확정: ① 플롯 = **맵 위 주사위 토큰** ② GM 도구 = **장서/마소 토큰**, **저항 목표치 계산**.
- 룰 근거: 기본 룰북(1.09.01) 13장 전투 장면, 16장 마법, 19장 원형. 아래는 문구를 옮긴 것이 아니라 요약이다. **[룰북]** = 룰북에서 직접 확인, **[Roll20]** = Roll20 스크립트에서 가져온 아이디어, **[미확인]** = 코드/실행으로 아직 확인 못함.
- 참고한 Roll20 스크립트: kibkibe/roll20-api-scripts 의 `magicalogia_*` 6종 (summon, match_dice, install_magic, resist, battle_turn, mana_token). README는 기능 설명만 있고, `match_dice` 소스만 읽었다.

## 1. 룰 요약

### 1-1. 마법전의 한 라운드 [룰북 13장]
라운드 개시(선공→후공 순으로 아무 마소 1점) → 선공 소환 → 후공 소환 → **선공 공격 스텝** → **후공 공격 스텝** → 라운드 종료.

### 1-2. 공격 스텝 (플롯이 쓰이는 곳) [룰북]
1. 공격측은 [공격력]개의 공격 주사위, 방어측은 [방어력]개의 방어 주사위를 얻는다.
2. 서로 **상의 없이** 눈을 정해 숨기고(플롯) 동시에 공개한다. 공개한 주사위는 각자 **주권**(주사위 배치 공간)에 놓는다.
3. 공격 주사위를 하나씩 **같은 눈의 방어 주사위**와 짝지어 서로 제거한다.
4. 공격 주사위가 하나라도 남으면 공격 성공, 남은 개수만큼 대미지(+[추가 대미지]). 하나도 안 남으면 방어 성공(추가 대미지도 없음).
5. 방어 성공/실패와 무관하게 방어측은 대미지 적용 후 주권에 남은 방어 주사위를 원하는 만큼 **마소로 변환**할 수 있다(눈에 대응하는 영역의 마소, 플롯한 본인만 획득).

### 1-3. 변형 규칙 [룰북]
- **입회인**: 대표가 방어할 때 입회인 전원이 **방어 주사위 1개씩 추가 플롯**, 공개 후 대표의 주권에 놓인다. 대표가 마력(또는 일시적 마력)을 잃으면 입회인 전원의 마력이 1 감소.
- **집중 방어**: [방어력] 3 이상, 무작위 플롯이 아닐 때만. 방어 주사위를 **두 개만** 위아래로 쌓아 플롯. 공개 시 공개된 방어 주사위가 그 두 개뿐이면 선언 가능 → 그 두 눈과 같은 공격 주사위를 **몇 개든** 제거. 이때는 마소 변환 불가. 입회인의 플롯은 평범한 방어 주사위로 처리.
- **무작위 플롯**: 효과에 따라 눈을 정할 수 없고 굴려서 정한다 (`?`).
- **[부스트n]** (원형 이펙트): 공개 후 라운드마다 1회, 공격/방어 중 한쪽에 n개를 추가로 **굴린다**(눈 선택 불가).
- **[블록n]** 등 대미지 경감은 공격 주사위를 제거하지 않는다.

> **Roll20 스크립트와의 차이**: `match_dice`는 A/B 각각 대표·입회 4구역을 서로 교차 비교하고 `0` 면/집중 구역 로직이 있다. 이 룰북의 흐름(공격 주사위 vs 방어 주사위, 입회인은 방어 +1)과 맞지 않는 부분이 있으므로 **그대로 옮기지 않고 룰북 기준으로 짠다.** 사용자의 테이블이 다른 판(전판)을 쓴다면 알려 달라.

### 1-4. 저항판정 [룰북 16장·19장]
- 주문의 목표가 된 쪽은 **그 주문의 지정특기**로 판정해 성공하면 효과를 무효로 한다. 지정특기가 없는 주문은 저항 불가. NPC와 **원형**도 저항할 수 있다.
- **캐릭터**: 자신의 특기표에서 그 특기의 목표치(이 시스템의 `computeTargets` 결과, 습득 5 · 불운 칸 제외 · 갭 규칙).
- **원형**: 특기를 1개만 갖고, 그 영역의 존재로 간주되며 **자기 영역 좌우 갭이 칠해진 것으로 간주**한다. 따라서 원형의 저항 목표치 = "원형의 특기 1칸만 습득, 그 영역의 갭(`gapsForCuriosity`)을 칠한 표"에서 지정특기 칸의 목표치.
- **[워드n]** (원형 이펙트): 자신 또는 자신이 사역하는 원형이 목표가 됐을 때, 목표치를 n으로 **변경할 수 있다**. 단 지정특기가 **워드 소유자의 영역**에 속하는 주문뿐.
- **주구 낭독**의 낭독 효과 중 "그 주문에 대한 저항 판정 -1" 선택지가 있다(세션당 효과 최대 3회, 같은 주문은 한 번).
- 불운/상태이상 등의 보정은 기존 판정 카드(`rollTalentCard`)의 보정과 같은 경로로 처리.

### 1-5. 충전과 마소 [룰북 16장]
- 코스트는 "짐승2"처럼 **영역 + 숫자**. 영역은 충전 가능한 마소 종류, "전"이면 아무 마소, 숫자는 사용에 소비하는 충전 마소 수. 마소는 사용 선언 → 목표 → 주구 낭독 → 코스트 소비 → 지정특기 판정 → 효과 순서에서 **코스트 소비 직전까지** 마련하면 된다.
- 룰북이 권하는 보조 도구가 바로 이것이다: 마법 하나하나를 **쪽지**로 만들고 마소를 나타내는 **토큰을 쪽지 위에 올려 충전**을 표시한다.
- 종료 페이즈 메인터넌스에서 충전 마소는 모두 0이 된다(이 시스템은 시트에서 충전 −/+ 로 관리 중. 확인: `actor-sheet-v3`).

## 2. 플롯 (맵 위 주사위 토큰)

### 2-1. 모델
- **주사위 토큰**: 값 1~6, `?`(무작위), 뒷면 상태. 값은 토큰 플래그(`flags.magicalogia.die = {value, faceDown, owner, role}`)에 두고 이미지는 값별로 교체한다(Token Variant Art 사용 가능). 값은 소유자와 GM만 볼 수 있어야 하므로 **뒷면 토큰은 공용 이미지**만 보이고 값은 소유자에게만 보이는 별도 표시로 둔다 [미확인: Foundry v12에서 토큰 이미지를 사용자별로 다르게 보이게 하는 방법, 가장 단순한 건 "소유자만 보는 레이어/숨김 처리 + 공개 시 교체"].
- **구역**: 장면 안에 이름 붙은 영역(드로잉 또는 타일) — `공격측 플롯`, `방어측 플롯`, `주권(공격측)`, `주권(방어측)`, 입회인 플롯 칸. GM이 한 번 배치하고 플래그로 역할을 지정.
- **공개**: GM(또는 양측 확인) 버튼 → 모든 뒷면 주사위를 뒤집고 `?`는 그때 굴린다 → 4번 규칙(§1-2)으로 비교.
- **실시간 변환**: 토큰이 이동/생성/삭제될 때(`updateToken`, `createToken`, `deleteToken` 훅) 구역별 주사위 목록을 다시 계산한다. 공개 후에는 제거된 주사위(짝지어진 것)를 흐리게 표시하고, 남은 공격 주사위 수 = 대미지를 계산해 **채팅 카드**로 올린다(기존 스티커 카드 디자인 + 연출 재사용).
- **마소 변환**: 방어 성공/실패 후 남은 방어 주사위를 눌러 마소로 변환(눈 → 영역) → 소유자 마소 처리는 직접(자동화 범위는 §4 질문).

### 2-2. 단계
1. 주사위 토큰 이미지/액터(또는 토큰 템플릿) 정의 + 구역 지정 도구.
2. 공개 + 비교 + 결과 카드 (입회인 방어 지원, 집중 방어 선언 포함).
3. 무작위 플롯, [부스트] 추가 굴림, 마소 변환.
4. 기존 대화상자 플롯(`plot.js`)과의 공존/대체 결정.

## 3. GM 도구

### 3-1. 장서/마소 토큰
- 장서(`ability` 아이템)의 이름·코스트·지정특기를 읽어 **마법 쪽지 토큰**(또는 타일)을 맵에 만들고, 영역별 **마소 토큰**을 쪽지 위에 올려 충전을 표시한다. 쪽지 위 마소 수 ↔ 시트의 충전 칸을 양방향으로 맞출지는 §4 질문.
- 코스트 영역과 다른 마소는 올릴 수 없게 막거나 경고("전"은 모두 허용).
- Roll20 `mana_token`은 저널(핸드아웃)에서 마법 설정을 읽는다. 여기서는 아이템 데이터를 직접 읽으므로 불필요.

### 3-2. 저항 목표치 계산
- 입력: **주문**(지정특기) + **목표** 토큰(캐릭터 또는 원형).
- 계산: §1-4. 캐릭터는 특기표, 원형은 "특기 1칸 + 영역 갭" 표, [워드n]이 있으면 선택적으로 덮어쓴다. 주구 -1, 불운 보정은 체크박스.
- 출력: 목표치를 보여 주고 **저항 판정 굴리기** → `rollTalentCard`로 채팅 카드(저항 성공이면 "효과 무효" 표시).
- 위치: 시트 안 버튼 + 토큰 우클릭 HUD 버튼 후보.

### 3-3. 원형 토큰 [후순위, 사용자가 이미지를 제공할 예정]
- 이름 입력으로 원형 토큰 생성(Roll20 `summon` 형). 이펙트([블록], [추가 대미지] 등) 수치를 플래그로 저장해 저항/플롯 계산에서 읽는다.

## 4. 사용자 결정 / 남은 확인
1. **판 구성: Roll20 스크립트처럼.** A/B 대표·입회 4구역 + 교차 비교 방식으로 간다(§1-3의 룰북 흐름과 다른 부분은 구현 전에 `match_dice` 소스를 다시 읽고 맞춘다. 불일치는 문서에 남긴다).
2. **이미지**: 사용자가 나중에 정리해서 제공. 그 전에는 이미지 없이 되는 작업(저항 목표치 계산 등)부터 한다.
3. **마소 변환**: 시트 자동 반영은 **하지 않는다**. 채팅 안내만.
4. **충전 동기화**: (질문이 불명확했음) 쪽지 위에 올린 마소 개수를 시트의 충전 칸과 같이 움직이게 할지의 문제. 답이 없으므로 **시트 값을 쪽지에 보여 주기만 하는 쪽**(단방향)으로 가정하고 진행하며, 필요하면 나중에 양방향으로 확장한다.
5. **원형/NPC 액터 구조** [확인함, `template.json`]: 액터 타입은 `character` 하나뿐이고 원형 액터는 없다. 그래서 **원형은 액터가 아니라 토큰(플래그)으로** 다룬다. 저항 계산은 "원형의 특기 1칸 + 영역 갭" 규칙(§1-4)으로 표 없이 계산한다 → 구현됨(`resistTargets`).

## 5. 구현 순서 제안
1. 저항 목표치 계산 (순수 함수 + 시트 버튼) — 가장 작고 테스트 가능. 기존 `talent-calc.js` 재사용.
2. 플롯 토큰: 구역 + 공개/비교 + 결과 카드 (입회, 집중 방어).
3. 장서/마소 쪽지 토큰.
4. 원형 토큰/이펙트.
